# Intraday Sample Collector v2.0 — One-Day Research Tool

## Purpose

Collect timestamped intraday observations on **2026-07-20 (Monday)** for research
and evaluation only. Samples are never published to users.

## Version 2.0 Changes (Blocker Resolutions)

| Blocker | Resolution |
|---------|-----------|
| B1: VPS timezone | Schedule expressed in WIB; verification commands provided |
| B2: True one-day | Year-aware date guard rejects any date != 2026-07-20 |
| B3: Summary race | Summary generated inline by the 16:00 process; no separate job |
| B4: Production overlap | Checks production lock file; waits or skips if active |
| B5: Fresh observations | Forces network fetch per snapshot; records full freshness metadata |
| B6: Universe scope | Deterministic top-200 from ticker list; 12-min runtime budget |

## VPS Timezone Verification (MUST DO BEFORE SCHEDULING)

Run these **read-only** commands on the VPS:

```bash
date
date '+%Y-%m-%d %H:%M:%S %Z %z'
timedatectl
cat /etc/timezone
crontab -l | head -5
grep -r CRON_TZ /etc/cron* 2>/dev/null || echo "no CRON_TZ found"
systemctl list-timers --no-pager 2>/dev/null | head -10
```

**Expected result:** `Asia/Jakarta` (WIB, UTC+7).

If the VPS timezone is **Asia/Jakarta (WIB)**, use the schedule below as-is.
If the VPS timezone is **UTC**, subtract 7 hours from each time.

After verification, update `VERIFIED_VPS_TIMEZONE` in the source code.


## Safety Guarantees

- No Telegram sends
- No production Day Trade publication or replacement
- No `telegram_daily_picks` registration
- No active recommendation state changes
- No recommendation monitor triggered
- No Swing Konglo / Swing Non-Konglo / Top5 calls
- No portfolio or user data modification
- No AI narration
- No candidate-state mutation
- `DAYTRADE_INTRADAY_SCORE_ENABLED=false` enforced
- Append-only local JSONL storage
- Production worker overlap detection
- Does NOT modify production cron

## Universe Policy (Deterministic)

- **Source:** First 200 tickers from `data/daytrade-observe-tickers.txt` (file order)
- **Same tickers every snapshot** — no random selection
- **Runtime budget:** 12 minutes maximum per snapshot
- If budget exhausted: records `timed_out_count` and continues with collected data
- Run record includes: `requested_count`, `attempted_count`, `completed_count`,
  `failed_count`, `timed_out_count`

## Data Freshness (Per-Snapshot)

Each snapshot **forces a fresh Yahoo network fetch** (cache TTL = 0 during sample).
If Yahoo fails, stale cache is used as fallback but explicitly marked:

Every candidate record includes a `freshness` object:
```json
{
  "provider": "yahoo_chart_1d",
  "fetch_timestamp": "2026-07-20T02:15:01.234Z",
  "fetch_duration_ms": 450,
  "network_fetch": true,
  "cache_hit": false,
  "cache_age_seconds": 0,
  "trading_day_candle_timestamp": "2026-07-20T00:00:00Z",
  "trading_day_candle_date": "2026-07-20",
  "is_stale": false,
  "stale_reason": null,
  "candle_count": 65
}
```

A stale fallback looks like:
```json
{
  "network_fetch": true,
  "network_failed": true,
  "cache_hit": true,
  "cache_age_seconds": 3600,
  "is_stale": true,
  "stale_reason": "network_failed_using_stale_cache_age_3600s"
}
```

## Production Overlap Handling

Before each sample run:
1. Reads `tmp/daytrade-vps-worker-observe.lock` (production worker lock)
2. If production PID is alive: waits up to 30 seconds
3. If still active after 30s: skips with `skipped_due_to_production_lock`
4. Records: `production_pid`, `production_started_at`, `waited_ms`

The sample collector does NOT alter or interfere with the production worker.


## Output Files

```
data/intraday-samples/2026-07-20/
  runs.jsonl         — run-level metadata per snapshot
  candidates.jsonl   — per-candidate observation records (with freshness)
  errors.jsonl       — any errors or safety violations
  lifecycle.json     — cross-observation candidate lifecycle tracking
  summary.json       — end-of-day summary (generated by 16:00 run)
```

## Manual Usage

```bash
# Single sample at a scheduled time
node tools/intraday-sample-collector.js --scheduled-time 09:15

# With custom limit
node tools/intraday-sample-collector.js --scheduled-time 09:15 --limit 100

# Dry run (no file writes)
node tools/intraday-sample-collector.js --scheduled-time 09:15 --dry-run
```

## One-Day Scheduling (True One-Time, NOT installed)

### Option A: Using `at` (preferred if atd is available)

```bash
# Verify at is available
which at && systemctl is-active atd

# Schedule all 21 jobs (example for WIB timezone VPS):
echo "cd /home/ubuntu/auto-cuan-runner && node tools/intraday-sample-collector.js --scheduled-time 09:15" | at 09:15 20.07.2026
echo "cd /home/ubuntu/auto-cuan-runner && node tools/intraday-sample-collector.js --scheduled-time 09:30" | at 09:30 20.07.2026
# ... (repeat for all 21 times)
echo "cd /home/ubuntu/auto-cuan-runner && node tools/intraday-sample-collector.js --scheduled-time 16:00" | at 16:00 20.07.2026
```

## Rollback & Cleanup

1. Cron entries are harmless after 2026-07-20 (script rejects wrong dates).
2. Remove cron block: `crontab -e` → delete the marked block.
3. Or remove at jobs: `atq` → `atrm <job_id>` for each.
4. Archive data: `tar czf ~/intraday-samples-backup.tar.gz data/intraday-samples/`
5. Delete: `rm -rf data/intraday-samples/2026-07-20/`
6. Remove code: delete `tools/intraday-sample-collector.js`,
   `lib/intraday-sample-lifecycle.js`, `lib/intraday-sample-summary.js`,
   `test/intraday-sample-collector.test.js`

No production state was ever mutated.

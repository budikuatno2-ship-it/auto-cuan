TRUST / OPERATING BOUNDARIES

Batas sistem harus lebih jelas daripada janji produknya.

Halaman ini merangkum cara Auto-Cuan diposisikan dan dijaga: sebagai alat bantu analisis pasar IDX, bukan mesin eksekusi transaksi. Tujuannya bukan membuat klaim besar, melainkan membuat batas produk dapat diperiksa.

01 / Operating boundary

Apa yang sistem lakukan — dan apa yang tidak.

Batas ini penting karena kualitas alat analisis tidak menghilangkan risiko keputusan investasi.

Peran sistem
Menyaring radar/watchlist dan menyajikan konteks analisis untuk dibaca pengguna.
Eksekusi transaksi
Tidak dilakukan oleh Auto-Cuan. Keputusan dan eksekusi tetap manual di sekuritas pilihan pengguna.
Dana & kustodi
Auto-Cuan tidak memegang dana pengguna. Portofolio di aplikasi merupakan pencatatan/alat bantu, bukan rekening kustodian.
Freshness
Data dapat terlambat atau stale. Status freshness dan warning harus dibaca sebelum keputusan dibuat.
Risiko pasar
False breakout, slippage, likuiditas, gap, dan risiko pasar lain tetap ada. Tidak ada tampilan UI yang menghapus risiko tersebut.
02 / Engineering controls

Kontrol engineering yang bisa diperiksa di repository.

Kontrol ini membantu mengurangi regresi dan perubahan berisiko. Mereka tidak sama dengan audit atau sertifikasi keamanan pihak ketiga.

Protected delivery

Perubahan production lewat pull request.

Branch production diproteksi dan perubahan harus melewati jalur review/status checks repository sebelum merge.

Static analysis

CodeQL dan repository security gate.

CI menjalankan pemeriksaan keamanan source dan repository guard sebagai bagian dari delivery gate.

Regression gates

Web hardening + focused tests.

Build production dan regression contracts dijalankan untuk menangkap perubahan yang melanggar kontrak runtime/UI yang sudah dijaga.

Cache boundaries

API dan application HTML memakai no-store.

Konfigurasi deployment membedakan asset statis cacheable dari route/API yang dikonfigurasi no-store.

Catatan: status CI yang hijau adalah kontrol engineering internal. Halaman ini tidak menyatakan Auto-Cuan memiliki sertifikasi eksternal, audit regulator, atau jaminan bebas kerentanan.
03 / Responsible disclosure

Temuan keamanan seharusnya masuk ke jalur yang tepat.

Untuk konteks source/repository, gunakan area Security repository. Hindari mempublikasikan kredensial, token, atau detail eksploit aktif di kanal publik.

# Evidence-based analysis rewrite with UI and session management polish

Auto-Cuan's AI analysis engine is completely rearchitected around an "Evidence Lock" system that constrains the LLM to only reference data actually provided. The ticker-only path (Level 1) caps scores at 55 and forbids technical claims without chart evidence; the chart path (Level 2) caps at 70. Alongside this, the frontend gains a wider layout (1500px), localStorage bloat protection via base64 stripping, relative dates and message counts in the sidebar, and a chart upload flow that now passes detected timeframe/ticker/price as additional context to the API.

**Watch for:** The `detectTimeframeFromFilename` function is the only source of timeframe data for chart uploads — if users don't name files conventionally, timeframe context is silently null and the prompt falls back to generic chart analysis without informing the user (confirmed). The `stripBase64FromHtml` regex replaces all data-URI images indiscriminately, including any non-chart images the AI may have rendered inline (confirmed). The fallback HTML in `generateFallback` still contains hardcoded confidence sub-scores (5/25, 12/25) that don't vary with the computed overall score, creating an internal inconsistency users might notice (confirmed).

## High-level view

The prompt rewrite is the centerpiece: the old prompt fabricated SMC claims (demand zones, BOS, volume signals) from ticker+price alone, and the new system explicitly forbids that. Score caps and strict recommendation labels enforce honesty about data quality. The 15-section output structure replaces the old 13-section layout, with new sections like "Data Quality Check" and "What Could Go Wrong" that surface uncertainty rather than hiding it. The `isCompleteAnalysis` validator was updated to match the new section names.

The chart upload flow now extracts metadata from the client side — timeframe from the filename, ticker from the message, price from the message — and passes it to the API, where it's appended to the chart prompt as "additional context." The timeframe detection is regex-based and only fires on conventional naming patterns like `BBCA-1D.png`; auto-generated screenshot names will miss.

The `stripBase64FromHtml` function fixes localStorage bloat by replacing data-URI images with placeholders before persistence. A note is shown when reopening sessions that had images stripped. The stripping is indiscriminate — all `data:image` URIs are hit, not just chart screenshots.

The UI changes widen the layout from 1024px to 1500px across all sections, expand AI bubble width to 92%, and make copy buttons always partially visible. The session sidebar gains relative dates, message counts, and an emerald left-border for active sessions.

## Evidence Lock and score capping system

The old `buildPrompt` fabricated entire SMC analyses from two numbers — claiming demand zones, higher lows, volume patterns, and giving scores of 65-75 with "LAYAK MASUK" recommendations. The rewrite introduces a tiered system: Level 1 (ticker + price) caps at 55, Level 2 (single chart) caps at 70, and scores above 70 conceptually require multi-timeframe data. Anti-hallucination rules explicitly list the SMC concepts that must not be claimed without chart evidence (BOS, CHoCH, FVG, order blocks, volume patterns).

The prompt prescribes a strict label vocabulary — twelve allowed recommendation labels with only four valid for Level 1. This prevents the LLM from dressing up uncertainty as actionable advice.

The `isCompleteAnalysis` validator now checks for new keywords ('Data Quality', 'Confidence', 'Invalidation', 'Final Decision', 'Risk Reward', 'Action Plan') with a threshold of 4/6, down from 5/6 on the old set. The minimum length dropped from 500 to 400 chars. A response that hits only 4 of 6 markers could be missing important sections like "Invalidation" or "Risk Reward" and still pass validation.

## Chart upload context enrichment

The client-side `handleChartUpload` now detects timeframe from the filename via regex, picks up the active ticker (or detects one from the message), and calls `detectPrice(msg)` to extract a price. All three are sent to the API as new body fields. On the server, `handleChartUpload` appends them to `CHART_SYSTEM_PROMPT` as a "KONTEKS TAMBAHAN DARI USER" section.

The timeframe regex covers `1w`, `weekly`, `1d`, `daily`, `4h`, `1h`, `15m` and Indonesian equivalents (`minggu`, `harian`, `jam`). Since most users screenshot from TradingView and their browser names the file `image.png` or a timestamp, the detection will fire rarely without explicit user naming. The chart prompt already instructs the LLM to identify timeframe from the image itself, so this is additive — but users have no feedback that their timeframe wasn't detected.

## Prompt injection surface in chart context fields

The new fields `ticker`, `currentPrice`, and `timeframe` from `req.body` are string-concatenated into the prompt:

```javascript
if (ticker) chartPrompt += '- Ticker: ' + ticker.toUpperCase() + '\n';
if (currentPrice) chartPrompt += '- Harga sekarang: Rp ' + currentPrice + '\n';
if (timeframe) chartPrompt += '- Timeframe chart: ' + timeframe + '\n';
```

No length check or character filtering. A malicious client could send `timeframe: "1D\n\nIGNORE ALL PREVIOUS INSTRUCTIONS..."` and inject arbitrary prompt content. The `ticker` field gets `toUpperCase()` but that doesn't strip newlines or control the length. The `currentPrice` and `timeframe` fields have no transformation at all. For a multi-user system with login, the attack surface is self-targeted (results return to caller), but prompt corruption from malformed input is still possible. Sanitize by stripping newlines and capping field lengths.

## Fallback HTML inconsistencies

`generateFallback` computes `supportEst`, `resistEst`, `invLevel`, `bestCase`, `worstCase`, and `score`. Only `score`, `supportEst`, and `resistEst` are actually interpolated into the template. `invLevel`, `bestCase`, and `worstCase` are dead code. The scenario section (section 12) uses hardcoded text like "sideways dalam range" where these computed values should appear.

The confidence sub-scores (5/25, 5/25, 12/25, 0/25) are static strings that always sum to 22, but the displayed overall score varies from 38-48 depending on price. Users who add the sub-scores will see they don't match the total.

## localStorage bloat protection

`stripBase64FromHtml` applies two regex passes: one catches `src="data:image/..."` attributes (replaces with `src="data:removed"`), the other catches bare base64 strings (replaces with `[gambar-dihapus]`). When a session with stripped images is reopened, the code detects the placeholder strings and appends an informational note. Analysis results are preserved — only source images are lost.

The risk is that the regex is broad: any `data:image` URI in any message gets stripped, not just chart screenshots. If a future AI response includes small inline data-URI icons or diagrams, they'll be silently removed on next save.

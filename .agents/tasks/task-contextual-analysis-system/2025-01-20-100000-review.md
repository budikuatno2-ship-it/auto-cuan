# Compact prompt rewrite, session memory, and UI polish for Auto-Cuan

The analysis backend (`api/analyze.js`) was gutted from a verbose 15-section prompt format down to a compact 7-section format, cutting the file from 1483 to 908 lines. Alongside this, the frontend (`index.html`) gained session memory that persists analysis context (ticker, score, decision, key levels) and feeds it back to the API for follow-up conversations. A third layer adds UI polish: progressive loading messages, a regenerate button, typing effect for short responses, and collapsible analysis output.

**Watch for:** Context string injection into the follow-up prompt carries unsanitized user-derived data (confirmed). The analysis collapsible split at "Action Plan" string index is brittle and can break the HTML mid-tag (likely). The `regenerateLastAnalysis` function removes the old bubble before confirming the new analysis will succeed (confirmed).

## High-level view

The prompt rewrite is the largest change by line count: `buildMarketMakerSection` went from ~130 lines to 27, `buildBrokerSummarySection` from ~100 to 31, and the main ticker prompt template was reorganized into a clear 7-section skeleton with explicit token budget rules per evidence level. The FCA hallucination fix removes `buildFCAContextBlock` from being appended when `fcaStatus === 'not_detected'`, eliminating the keyword surface the model was picking up on.

Session memory (`latestAnalysisContext`) stores structured data extracted via regex from AI response HTML. This data is serialized into a context string and injected into the follow-up system prompt verbatim — without the sanitization applied to document uploads elsewhere in the codebase. Follow-up detection uses a broad regex of common Indonesian and English trading phrases, which can false-positive on messages about different stocks.

The UI additions (progressive loading, typing effect, collapsible, regenerate) are self-contained DOM manipulations. The collapsible analysis splits the HTML string at the first occurrence of "Action Plan" — a text-offset split that can land mid-tag. The regenerate button removes the existing analysis bubble before confirming the replacement will succeed.

<details>
<summary>Issues (5)</summary>

1. **Context string prompt injection** — The follow-up prompt interpolates `latestAnalysisContext` (which includes regex-extracted strings from AI output) directly into the system prompt without sanitization. A crafted AI response or manipulated localStorage could inject instructions. Sanitize or escape the context string before interpolation, or pass it as a separate `context` message part rather than embedding in the system prompt text.
2. **Collapsible split breaks HTML** — `html.indexOf('Action Plan')` splits at a raw text offset which can land inside an HTML tag or attribute, producing broken DOM. Use a structural split (find the enclosing `<div>` boundary around the Action Plan heading) instead of string index.
3. **Regenerate removes bubble before success** — `regenerateLastAnalysis` calls `bubble.remove()` immediately, then triggers the async analysis. If the re-analysis fails, the user sees an error bubble but the original analysis is already gone. Remove the old bubble only after confirming a successful replacement.
4. **Typing effect renders partial HTML** — The typing effect slices `fullContent` at arbitrary character offsets (`charIdx += 4`), which will produce broken HTML tags and visible angle brackets during the animation. Either use `textContent` for the animation or parse the HTML into text segments first.
5. **Follow-up detection false positives** — The follow-up regex (`/gimana|bagaimana|kenapa|why|lanjut|terus|kalau.../i`) will match any message containing these common Indonesian words (e.g., "kalau GOTO gimana?" about a different stock) as long as *any* prior context exists. Consider also matching the active ticker in the message or requiring the message to lack a new ticker.

## Context string injection into follow-up prompt

The `handleChatMode` function in `api/analyze.js` builds the follow-up system prompt by interpolating the context string directly:

```javascript
chatSystemPrompt = `...Konteks analisis terakhir: ${ctxStr}...Pertanyaan user: ${message}`;
```

`ctxStr` originates from `latestAnalysisContext`, which is populated by `extractAnalysisContext(html)` on the frontend. The extraction pulls substrings out of AI-generated HTML via regex. If the AI output contains adversarial text (or if localStorage is tampered with), those strings flow unescaped into the system prompt. The `sanitizeDocumentText` function exists for document uploads but nothing equivalent sanitizes the context string.

This isn't a remote exploit (it requires either LLM output manipulation or localStorage access), but it defeats the prompt-injection defenses applied elsewhere in the codebase. The fix is to either sanitize the context string server-side with the same delimiter-stripping logic used for documents, or restructure the prompt to pass context as a separate content part rather than inlined text.

## Collapsible analysis HTML split

```javascript
var splitIdx = html.indexOf('Action Plan');
if (splitIdx === -1) splitIdx = html.indexOf('</div>', 300);
if (splitIdx === -1 || splitIdx < 100) splitIdx = 300;
```

This splits the raw HTML string at a text-content offset. If "Action Plan" appears inside an attribute value, or if the split lands inside `<div class="...">`, the resulting `previewHtml` and `fullHtml` fragments will produce broken DOM. The fallback at character 300 is purely positional with no structural awareness.

A safer approach: render the full HTML into a detached container, walk the DOM to find the Action Plan heading, then split at that element boundary.

## Regenerate removes bubble optimistically

```javascript
function regenerateLastAnalysis(btn) {
    var bubble = btn.closest('.flex.gap-3');
    if (bubble) bubble.remove();
    if (lastAnalysisParams.type === 'chart_upload') {
        addAIBubble('...Tidak bisa mengulang...');
        return;
    }
    // ...triggers async analysis
}
```

The bubble is removed synchronously. If the subsequent `handleAnalysis` call fails (network error, API timeout, rate limit), the original content is permanently lost. The user sees an error message where a complete analysis used to be.

## Typing effect on raw HTML

```javascript
aiContentEl.innerHTML = fullContent.slice(0, charIdx);
```

For a response like `<p class="text-sm text-gray-300">Hello</p>`, intermediate renders produce `<p c`, `<p clas`, etc. The browser attempts to parse these as HTML, producing garbled output during the animation and potential unclosed tags that corrupt the surrounding DOM. This affects non-structured responses under 500 characters — the most common chat replies.

## Follow-up detection breadth

```javascript
var followUpPattern = /gimana|bagaimana|kenapa|why|lanjut|terus|kalau|apa.*berikutnya|masuk.*gak|beli|jual|hold|cut|entry|target|stop.*loss|risk/i;
if (latestAnalysisContext.ticker && latestAnalysisContext.score && followUpPattern.test(msg)) {
    chatSource = 'follow_up';
}
```

Words like "kalau", "terus", "beli", "jual" are extremely common in Indonesian chat. Any message containing these words will be classified as a follow-up if *any* prior analysis context exists, even if the user is asking about a completely different stock. The `follow_up` source triggers the compact 150-400 word response and skips the normal chat system prompt, which means the user gets a contextually wrong answer framed as a follow-up to the previous ticker.
